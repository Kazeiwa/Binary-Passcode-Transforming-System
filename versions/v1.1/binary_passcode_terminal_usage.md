# 二进制密码转换终端 V1.1

Windows 10/11 x64 可直接双击 `binary_passcode_terminal.exe`，无需安装Python或另外附带运行库DLL。也可以使用 Python 3 运行 `binary_passcode_terminal.py`，不需要安装第三方 Python 包。两版密文和本地密钥互通。

Android可安装 `binary_passcode_terminal.apk`，支持Android 8.0及以上的ARM64、32位ARM和x86_64设备。手机端提供加密、解密、密钥三个页面，复用同一份C++核心，与桌面Python及EXE密文互通，无需安装Python。

## 操作

首次使用请选择“3 密钥管理”，导入双方约定的128位数字密钥，或生成新密钥。密钥开头的零必须保留。

- 1 加密正文：输入文本，得到固定200位数字密文。
- 2 解密密文：输入完整密文，显示正文和生成时间（北京时间，精确到分钟）。
- 3 密钥管理：查看配置状态、导入或更新密钥、生成新密钥、显示当前密钥。
- 0 退出程序。

每次操作后自动返回菜单。更换密钥前，请先备份旧密钥，以便读取使用旧密钥生成的消息。

## 正文

支持BMP（基本多文种平面）内的所有Unicode标量值，即U+0000—U+FFFF中除代理码点U+D800—U+DFFF以外的范围。包括简繁汉字、日文、韩文、希腊文、俄文、全角标点和 `@#$^&’` 等符号。

已有基础编码保持不变：大小写英文字母、半角数字、空格、英文逗号和句号、反斜杠、竖线，以及以下英文半角符号继续使用短编码，不重复加入Unicode转义：

```text
+-*/=!%_:;?"<>()[]{}
```

最多100字符，同时受100个编码单元的容量限制。基础字符以外的BMP字符各占6个单元，大小写及数字混合输入还会占用额外容量；超过容量时会提示缩短正文。代理码点不能作为独立字符；补充平面字符（如部分表情、生僻汉字）仍不支持。

底层编码也可以表示控制字符、组合字符、未分配码点及非字符码点；能编码不等于终端一定能显示。组合字符不会自动合并或归一化。桌面命令行界面按单行读取正文，换行会提交输入，因此不能通过普通粘贴直接录入多行正文；安卓正文输入框支持多行。Tab、NUL等控制字符能否输入及如何显示取决于终端。程序接口本身可以往返处理这些BMP标量值。

本次扩展可读取此前使用加密时间区的密文；包含新增字符的消息需要两端都更新程序。

短消息末尾补齐的空格会保留在解密结果中。

## 本地密钥

Windows：密钥加密保存在程序旁的 `binary_passcode_terminal.key` 中，请将程序放在允许写入的目录。该文件与本机账户绑定，不能直接复制到另一台电脑或其他账户使用。需要在另一台电脑使用时，请显示并复制原始128位密钥，再在目标电脑导入。

升级时，如果新文件名的密钥文件不存在，程序会在同目录查找旧的 `decimal_cipher_200.key` 并迁移；已有的新文件不会被旧文件覆盖。内部文件格式保持兼容。

Linux：密钥保存在系统密钥环中。需要已登录桌面会话、有可用的Secret Service密钥环服务，并安装 `secret-tool`。Debian/Ubuntu可使用：

```sh
sudo apt install libsecret-tools
```

登录密钥环通常会随桌面登录解锁，具体取决于桌面设置。缺少工具、密钥环未解锁或服务不可用时，程序会提示原因，不会退回明文文件保存。纯SSH环境未必提供可用的桌面密钥环。

Python版与C++版在Linux上使用相同的密钥环条目；更换其中一方保存的密钥，也会影响另一方使用的密钥。

Linux新条目的application属性为 `binary_passcode_terminal`；未找到新条目时，会读取旧的 `decimal_cipher_200` 条目并迁移。旧条目保留用于历史程序，新版后续更新写入新条目。

Android：原始通信密钥使用Android Keystore中的设备本地AES密钥进行AES-GCM加密，密文保存到应用私有存储。应用不申请联网或外部存储权限，不把原始密钥写入明文文件。卸载、清除应用数据或更换设备前应主动备份原始128位密钥；系统加密记录不能当作跨设备备份。

## 其他说明

本版使用加密时间区，可记录北京时间2000-01-01 00:00至2190-02-17 10:39。原有明文日期格式的实验版不能与本版混用；旧密文可用保留的 `decimal_cipher_200_v2_legacy.py` 读取。

密文长度不足、包含非半角数字、校验失败或字段无效时会报错。校验码用于检查输入错误，不能保证识别所有错误密钥或人为修改。

Windows密钥存储和加解密已完成实际运行测试；Linux密钥环调用通过模拟测试。Android的JNI桥接与Python完成100组主机JVM互通测试，APK通过v2/v3签名及16KB对齐检查；尚未在真实Android手机或模拟器验证界面及Keystore读写，也未在真实Linux桌面环境验证。
