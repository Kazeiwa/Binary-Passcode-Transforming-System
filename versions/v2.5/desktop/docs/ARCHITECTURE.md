# 协议与扩展结构

## 模块边界

| 模块 | 职责 |
|---|---|
| `bip/codec.py` | 五位状态编码，六单元BMP转义，60,000单元打包 |
| `bip/protocol.py` | 300,000比特正文封装、Unix秒数、HKDF用途分离、HMAC掩码和认证 |
| `bip/erasure.py` | GF(256)系统Vandermonde擦除码，任意k块恢复 |
| `bip/image_transport.py` | 版面规划、三点标记、RGB三通道独立传输、块内RS、裁剪与旋转识别 |
| `bip/vault.py` | 加密多密钥库、系统保护/主密码、备份、并发保存保护 |
| `bip/gui.py` | Tk界面、后台任务、进度及取消；不复制加密算法 |
| `bip/legacy20/` | 已发布V2.0格式的独立兼容快照；新消息只使用2.1 |
| `binary_image_passcode.py` | GUI入口和可选命令行 |

核心API为`encode_file`、`decode_file`，也提供`encode_array`、`decode_array`供测试和其他前端调用。返回结构是不可变dataclass，前端不必解析内部二进制数据。

## 固定消息封装

所有整数为大端序，位序为MSB优先。正文为300,000比特，即37,500字节；额外两个加密元数据字节存储实际使用的编码单元数（最大60,000），准确保留末尾空格。

```text
header: >4sBBBB48s5s                    61字节
  magic=BIP2                            4
  protocol_version=2                    1
  codec_id=1                            1
  transport_profile=2                   1
  flags=0                               1
  随机编号                              48
  加密Unix秒数                           5
加密元数据：实际编码单元数                2字节
加密正文                            37,500字节
HMAC-SHA256认证                        32字节
合计                               37,595字节
```

容量为300,000正文比特，整个认证信封为300,760比特。该格式不同于旧版200位十进制密文；128位共享密钥及字符表可以复用。V2.0图像由隔离的旧版解码器读取，原20,000单元、分钟时间和多数表决均保留原语义。

时间为标准Unix秒数，UTC起点1970-01-01 00:00:00，范围0—9,999,999,999，舍去小数秒，超出范围报错。加密时间是Unix秒数与密钥派生偏移量相加后模10^10，保存为5字节大端整数。10位十进制是数值范围定义，不是把时间保存成10个ASCII字符。该范围需要34比特，使用40比特容器便于字节封装，最高6比特必须为零；完整认证也覆盖该字段。解密显示北京时间，精确到秒，不显示原始时间戳。

HKDF-SHA256以128位数字的ASCII字节为输入，按用途派生32字节子密钥。消息相关子密钥使用48字节随机编号作salt；定位前缀使用固定零salt以便在恢复随机编号前读取块头。用途标签以`binary_image_passcode/v2.1/`开头；V2.0兼容解码仍使用原v1标签。

正文及两个长度元数据字节与HMAC-SHA256扩展掩码异或。每个分块输入包含用途、5字节Unix秒数、48字节随机编号和两字节分块序号；共1,172个块。完整信封认证覆盖原始头部和全部加密数据，先验证后解密。CRC或公开哈希不能替代该认证。

## 抗裁剪传输

### 外层擦除码

消息信封先补随机字节，再分成k个等长源块。GF(256)使用本原多项式0x11D，构造n×k Vandermonde矩阵，并乘以前k行的逆矩阵，得到系统生成矩阵。前k块保留原源数据，其他为冗余；任意k个独立、经过认证的数据块可以恢复信封。

n等于实际布局块数，最多196。均衡k=ceil(n/2)，增强k=ceil(n/3)，且k至少8；单块容量不够时拒绝该图片，不降低冗余。源块大小为ceil(37595/k)。部分损坏的包必须通过块内纠错及认证后才能参与外层恢复，否则视为丢失。

### 分布式定位

每块是128×128像素。三个14×14定位图样的左上角为(8,8)、(106,8)、(8,106)，每个外侧保留2像素安静区。图样为7×7二维码式同心方环放大2倍；它只是借用三点几何原理，不是标准二维码。

标记只写在R通道最低位中，G/B不承担标记备份，可继续存放独立数据。解码器按256行分条构造R通道积分图（额外重叠13行），匹配同心方环，允许每个标记最多12个不匹配位；必须找到符合固定距离的三个标记及完整128×128区域。数据通道在选中位置上按需提取奇偶，不复制整张图的三份位平面，以限制大图峰值内存。

因此可恢复平移裁剪、90度倍数旋转，而不需要原始宽高。当前不从被切断的部分块恢复数据。插值缩放会改变像素值，单靠三点定位不能解决；任意角度旋转、镜像和JPEG也不在该配置的保证范围内。

### 块封装与位置

每块头部采用`>4sBBBB48sBBBBHI`，合计66字节：标识BIPT、版本/配置/编码/标志、48字节消息编号、块序号、k、n、保留值、块大小、原始信封大小。

头部单独增加32字节RS校验，合计98字节。数据块加16字节截断HMAC认证后，再按RS(255,223)分块增加纠错；最后一块使用短码。块认证同时覆盖原始块头和数据。

每块有128×128×3个通道槽位，排除三个18×18区域的R槽位后，48,180个槽位为候选。前缀位置由固定用途的密钥派生结果决定；数据位置由密钥、消息编号和块序号决定，并排除前缀位置。SHAKE256生成排序键，排序后形成无重复槽位序列，不依赖语言内置随机数实现。槽位s对应像素s//3、通道s%3，通道依次为R/G/B。

每个槽位只写入一个独立比特，通道值最多变化1；三个通道不交叉备份，也不多数表决。块内RS纠错、外层擦除码和HMAC继续保护数据。界面的“写入通道比例”以整图W×H×3个槽位为分母，不与V2.0的像素比例直接混用。

### 自适应版面

留白比例m=min(12%,4%+2%×log2(max(1,W×H/1048576)))，四边分别排除ceil(W×m)、ceil(H×m)。在内部按128像素计算可放置行列数；超过196块时，在合法整数网格中选择块数尽可能多且长宽比接近图片的布局。行列坐标均匀分布于剩余区域，不重叠，不在固定角落集中写入。

均衡模式的总像素下限为313,600，增强为484,416，短边硬下限为140像素；还须满足完整块数量和容量检查。方图最低参考分别为560×560、696×696，推荐1024×1024及以上。读取裁剪图不套用这些编码下限。最大输入为8,000万像素、单边20,000。

解码不使用这些全图行列位置。定位只依据剩余图片里的局部三点标记，因此裁剪改变整图宽高不影响剩余完整块的局部解码。

## 密钥库

整个密钥列表（包含名称、原始密钥、默认ID）由AES-256-GCM加密，随机96比特nonce每次保存重新生成。系统保护方式使用随机库主密钥：Windows用DPAPI封装，Linux用Secret Service保存；主密码方式使用Scrypt（N=32768,r=8,p=1）派生主密钥。

加密备份使用独立盐、nonce和用户输入密码，不依赖原机器。所有读取均先认证再解析记录。跨进程保存使用文件锁与版本摘要，过期窗口不能覆盖其他窗口的新数据。保存先写临时文件、fsync、原子替换；POSIX文件权限为0600。

库保护不等于内存保护；Python无法保证字符串被完全擦除。库主密码、备份密码遗失均无恢复后门。通信共享密钥一旦泄露，可以读取使用它的历史图片；该版没有前向保密或重放防护。

## 后续扩展原则

新增字符编码、纠错布局或变换域载荷时应分配新的ID，保留旧版解码器；不要原地修改配置2的标记尺寸、字段顺序和派生标签。当前协议版本2、传输配置2；V2.0协议版本1保存在legacy20中。可复用现有密钥库与GUI，用新传输模块替换图像层。

若要支持压缩/缩放后的图片，应设计新的信号嵌入层并重新测试，而不是仅调整定位点阈值。若要更换为标准AEAD正文封装，也应分配新的协议版本，保留目前“先认证后输出”的约束。

参考：[HMAC](https://www.rfc-editor.org/rfc/rfc2104)、[HKDF](https://www.rfc-editor.org/rfc/rfc5869)、[Reed–Solomon FEC](https://www.rfc-editor.org/rfc/rfc5510)、[cryptography AEAD接口](https://cryptography.io/en/latest/hazmat/primitives/aead/)、[reedsolo文档](https://pypi.org/project/reedsolo/)。这些来源描述基础原语，不代表此自定义协议已获其安全认证。
