# 二进制图片密码 V2.6 · iOS / iPadOS

**当前交付是iOS源码项目，不附带IPA。** 用户已反馈上一版可以成功编译。本次新增解密图片默认存入相册、明确的保存/刷新反馈和两页图片独立状态，已通过本地语法与工程检查，仍需重新云端编译和设备验证。当前本地制作环境是Windows，不能执行iOS模拟器，真机结果以实际安装测试为准。详见TEST_REPORT.md。

## 功能

- 加密、解密文字和图片；自动识别消息类型。
- 文字最多60,000编码单元。英文大小写、数字、基础标点与BMP字符；扩展字符通常6单元，状态切换也占单元。表情和BMP外字符暂不支持。
- 图片尺寸自动适配至长边1920、短边1080以内，保持比例。
- JPG模式按底图容量自动压缩；PNG无损模式保留尺寸/方向适配后的8位RGBA像素，容量不足即报错，不进一步压缩正文。
- 输入底图可使用PNG、JPG及系统支持的BMP、HEIF等静态图片；所有含密文的输出均为PNG。
- 底图、正文图片和待解密图片均支持“从相册选择”和“从文件选择”。相册使用系统照片选择器，只读取用户选中的图片，不要求整个相册的访问权限。
- JPG与文字使用分块纠删码、RS纠错和定位标记；裁剪后能否恢复取决于剩余有效块。PNG无损图片使用高容量布局，需要完整像素，不支持裁剪。
- 底图和正文图片并排预览，点按可放大。保存密文PNG及还原的文字/JPG/PNG。
- 加密生成的密文PNG和解密后的图片均默认保存到系统相册，保留另存文件。首次保存只申请添加照片权限；保存期间显示进度，完成后弹窗反馈结果。密文按原始PNG资源写入相册，不经过UIImage转码。
- 加密和解密页面各自保留选择的图片及文件名，不会将解密载体自动带入加密页。
- 与Windows / Android V2.6密文格式互通；支持V2.1文字格式，不包含更早V2.0兼容分支。
- 生成时间加密，解密显示北京时间，精确到秒，不显示Unix时间戳。
- 128位十进制密钥；多密钥保存、选择、重命名、删除；本地系统钥匙串存储；带密码的密钥备份。

## 系统与安装

目标为iOS / iPadOS 16及以上，原生SwiftUI界面，无需Python。最低版本不是已完成真机验证的兼容性声明。

IPA不能像APK一样直接安装。Apple要求按所选渠道对应用签名：开发调试、已注册设备分发或TestFlight等。免费Apple账户通常可借助Xcode进行个人设备调试；更广泛分发需要相应开发者资格、证书和配置。

在Mac安装完整Xcode（建议16及以上），打开`binary_image_passcode.xcodeproj`，在应用目标的Signing & Capabilities中选择自己的Team，并将Bundle Identifier改成自己可用的唯一标识。连接iPhone，按Xcode提示启用开发者模式，选择设备后运行。请先运行项目内NativeTests。

### 导出IPA

Mac终端进入本目录，先运行测试：

```sh
python3 build_ios.py --test
```

模拟器测试使用无需Apple开发者证书的本地ad-hoc签名，并为模拟器应用提供钥匙串访问声明。`App/Simulator.entitlements`仅对`iphonesimulator`生效，不用于真机归档。测试仍读写真实模拟器钥匙串，不使用虚假存储替代。

已有可用开发者团队与签名配置时：

```sh
python3 build_ios.py --team YOUR_TEAM_ID --bundle-id your.unique.binarypasscode --method debugging
```

脚本将进行设备归档并导出，IPA位于`dist/signed/`。签名是否成功取决于这台Mac上Xcode登录的Apple账户、团队权限、设备注册和签名配置。

也可先编译未签名IPA：

```sh
python3 build_ios.py --unsigned
```

未签名包位于`dist/binary_image_passcode_v2.6_unsigned.ipa`，**必须另行签名才能安装**。脚本不会把源码压缩成冒充IPA的文件，也不会上传源码、消息或密钥。

### 没有Mac时

源码包内包含手动触发的GitHub Actions工作流。将本目录作为仓库根目录（务必包含隐藏的`.github`目录）后，可运行Build iOS V2.6，使用macOS构建机进行原生测试和未签名IPA编译。最新修订仍需重新运行并根据Xcode结果验证。产物仍需自己的合法签名；工作流不含证书、私钥或开发者账户。

成功时可下载`binary_image_passcode_v2.6_ios_unsigned`。无论成功与否，工作流都会尝试上传`binary_image_passcode_v2.6_ios_diagnostics`，包含测试结果与构建日志。测试失败时仍保持失败状态，不继续导出IPA。

## 使用方法

1. 打开“管理密钥”，随机生成或粘贴对方提供的128位数字密钥，命名保存并选用。前导零不得删除。
2. 加密时点击“选择底图”，选择“从相册选择”或“从文件选择”；图片正文入口也提供这两种来源。再输入文字或选择正文图片，按需启用PNG无损或增强裁剪恢复。
3. 生成后选择“保存密文PNG到相册”，允许添加照片后保存到系统相册，也可选择“另存密文PNG为文件”。发送时按文件/原图方式传递，避免聊天软件转换、缩放或截图。
4. 接收方选择同一密钥，在解密页从相册或文件选择收到的PNG。认证通过后才能显示正文或保存还原图片。图片消息点击“保存到相册”，允许添加照片后直接存入系统相册；保存成功会弹窗提示。需要保留文件时可选择“另存为文件”。

相册导入读取系统提供的当前图片文件，不通过UIImage重新编码，并尽可能避免系统转码。读取iCloud照片可能需要等待下载。密文请选未经编辑的PNG；若相册中的图片已被修改或转换，改为从“文件”选取接收的原始文件。

底图均衡模式至少313,600像素，增强模式至少484,416像素，短边至少140。推荐1024×1024及以上。实际长宽比必须能放下足够多的128×128数据块，因此满足总像素下限并不保证足够容量。PNG无损图片通常需要更大底图，其容量按图片大小计算。

底图最多8,000万像素、单边20,000，输入文件最多150 MiB；设备剩余内存不足时会提前拒绝，手机实际可处理的上限可能更低。正文图片自动缩小，不要求原始尺寸小于1080P，但仍受文件读取、格式和内存限制。

## 密钥保存与备份

“随机生成”和“保存并选用”为两个独立按钮。保存时使用输入框当前的128位数字，成功后显示已保存提示并选用该密钥，不会自动生成或替换密钥。已保存密钥可以通过右侧菜单“查看密钥”核对。

“刷新密钥列表”重新读取本机钥匙串中的密钥，单击后显示“已刷新，共N个密钥”。它用于刷新当前列表，不会打开另一份密钥文件或生成新密钥；读取失败会显示错误原因。

密钥仅保存在当前应用的系统钥匙串项目中，使用WhenUnlockedThisDeviceOnly保护，不通过iCloud同步，不把密钥存进偏好设置。偏好设置只保存选中密钥的随机ID。删除密钥会影响历史消息解密；请先导出带密码备份。

备份采用PBKDF2-HMAC-SHA256（210,000轮、16字节随机盐）和AES-256-GCM，密码至少10字符。备份容器标识BIPIK1。此格式供iOS版本使用，与桌面/安卓备份容器不同；跨平台可以导入同一128位数字密钥。导入采用合并，认证或格式失败时保留原有密钥。查看页复制的密钥仅留在本机剪贴板，并设置60秒过期。

切到后台时界面盖上隐私遮罩，以减少应用切换预览泄露；iOS不能保证阻止所有截图或录屏。应用不内置远程服务器、统计SDK或网络上传功能；使用云端“文件”位置时，文件提供方的同步行为由系统和用户所选服务决定。

## 构建结构

- `App/`：SwiftUI、Files导入导出、钥匙串、CryptoKit桥接及Objective-C++服务。
- `Core/`：跨平台C++17五位编码、消息认证、纠删码、RS纠错、SHAKE位置置换、RGB奇偶嵌入、PNG像素编解码。
- `Vendor/`：固定版本stb_image与stb_image_write，自带MIT/公有领域许可全文。
- `Tests/`：Python互通测试、Windows主机测试加密后端、待在Xcode运行的原生测试与合成样例。
- `Tests/KeyManagerUITests.swift`：手动输入密钥、保存、查看以及重启后逐字比对的界面回归测试，已加入共享Scheme；会在`build_ios.py --test`中运行。
- `generate_project.py`：确定性生成Xcode工程，无需CocoaPods、XcodeGen或第三方包管理器。
- `build_ios.py`：在Mac上测试、归档、签名导出；Windows上明确拒绝构建。
